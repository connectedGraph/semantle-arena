# 引擎与相似度

## 结论先行

**用腾讯 AI Lab 中文词向量（200 维，14.3 万词）**，不是句向量模型。

我一度换成了 BGE 句向量（理由是「腾讯词向量缺新词」），实测后那个理由站不住，
而且 BGE 在猜词场景下明显更差。同题对照（12 个答案 × 6 个「人类会想到的词」，
候选集都限制在同一个词池里）：

| 指标 | 腾讯词向量 | BGE |
|---|---|---|
| 前 10 命中 | **58%** | 30% |
| 前 50 命中 | **86%** | 68% |
| 前 200 命中 | **92%** | 82% |

差距最大的几例：

| 探针 | 腾讯名次 | BGE 名次 |
|---|---|---|
| 面包 → 蛋糕 | 8 | 357 |
| 电脑 → 显示器 | 6 | 421 |
| 面包 → 饼干 | 2 | 152 |
| 电脑 → 键盘 | 8 | 97 |

## 根因：词向量比句向量更适合「猜词」

BGE 是**句级**编码器。输入两个字的短词时，它没有句子上下文可用，
退化成依赖字面形态和通用的「名词性」——于是给出的是**同一个词的变体**：

```
BGE · 粘贴 的最近邻
黏贴 黏合 黏连 粘合 粘结 粘住 粘连 胶粘     ← 全是「粘」字族
```

上面这 8 个词占了前 16 名里的一半。玩家猜「粘贴」，拿回一堆几乎同义的变体，
语义空间被同族词挤满，感受不到「换领域」的乐趣。

腾讯词向量是在大规模语料上按**共现**统计出来的，
「粘贴」和「胶水」「胶带」「打印」经常出现在同一批上下文里：

```
腾讯 · 粘贴 的最近邻（限当前词池）
胶水 打印 填充 胶带 复制 拼接 模板 放置 填写 字体 链接 编码 拷贝 序号 格式 插入
```

前 30 名里有 `胶水 / 胶带 / 铁丝 / 焊接 / 固定 / 装饰`——都是**具体的东西**，
领域在跳跃。这才是猜词游戏想要的语义结构。

那为什么「黏贴」在腾讯里也排第一（0.89）？因为它是真的近义词。
但它后面立刻就是别的领域，不像 BGE 那样一整屏都是变体。

## OOV 怎么处理

腾讯词向量 14.3 万词，当前词池覆盖 **90.3%**。

池外词（支撑「猜词不限」）用**组成汉字的向量平均**近似：

```python
def mean_of_chars(word):
    vecs = [vectors.get(ch) for ch in word]   # 每个汉字的向量
    return normalize(np.mean(vecs, axis=0))
```

「干饭搭子」拆成 `干/饭/搭/子` 四个字的向量求平均。
这个近似很粗糙——它只反映「这些字常在什么语境里」，
不反映组合后的含义。所以池外词的结果会标 `approx=True`，界面上显示「估算」徽标，
避免玩家把「干饭搭子 vs 苹果 = 37%」理解成「不接近」。

## 字符重叠惩罚（保留，但系数降了）

词向量也有同字干扰，只是比 BGE 轻得多。惩罚项保留，系数从 0.15 降到 0.06：

```
排序分 = 语义相似度 − 0.06 × 共享汉字比例
共享汉字比例 = |A ∩ B| / min(|A|, |B|)
```

`粘贴` vs `黏贴` = 0.5（共享「贴」），会扣 0.03。
这个量级刚好压住同字变体，不影响 `钢琴 ↔ 音乐`（无共享字，不扣）。

**原始余弦相似度照常输出**，惩罚只作用于名次与排序。
界面上显示的百分比仍是「语义有多近」，不会被惩罚项改写。

参数在 `data/engine_config.json`：

```json
{ "char_penalty": 0.06, "semantic_blend": 1.0 }
```

## 词库档位

1.6 万词的池子抽到冷门词时难度失控（`拨通 / 产于 / 蒽醌`）。
所以做了三档，可在 UI 顶部切换：

| 档位 | 词数 | 说明 |
|---|---|---|
| 精简 | 3000 | 日常具象词，抽到的你都认识 |
| 标准 | 8000 | 有一定挑战 |
| 完整 | 16033 | 全量，会抽到冷门词 |

**默认精简档。**

选词方法见 `scripts/build_tiers.py`，核心是「具象种子投票」：
一批无可争议的具象日常名词（按领域分组，各 10~16 个）各投出自己前 250 个近邻，
得票高的就是具象词。实测筛出来的全是 `拖鞋 / 沙发 / 自行车 / 耳机 / 树叶 / 柜子` 这类。

为什么不用「按词频取前 N」：那样得到的是 `策略 / 数量 / 反映 / 要求 / 全球性`——
新闻语料的抽象高频词。玩家看到答案会想「这也能猜？」，比冷门词更难，
因为不知道往哪联想。

## 性能

| 环节 | 耗时 | 频率 |
|---|---|---|
| 启动加载 | ~1.5s | 每次启动（词向量 mmap） |
| 切档位 | ~0.3s | 每次切换（拼矩阵） |
| 猜词（池内） | < 1ms | 每次猜词 |
| 猜词（池外） | ~0.1ms | 每次猜词（4 个字向量平均） |
| 首次猜词建名次表 | ~15ms | 每局一次 |

比 BGE 快一个数量级——没有神经网络推理，纯点积。

## 换词表 / 换档位

```bash
# 换词表口径
python scripts/build_wordlist.py --min-freq 100 --dry-run
python scripts/build_wordlist.py
python scripts/build_tiers.py          # 重算档位（档位依赖词池）

# 换默认档位
ARENA_TIER=medium ./run.sh
```

换词表不需要改游戏逻辑——引擎按词池 + 档位取词，其余照常。
