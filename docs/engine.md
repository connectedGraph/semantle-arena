# 引擎与相似度

这份文档解释语义引擎的技术选择，以及为什么「换词表」是安全的。

## 为什么不用词向量表

上一版用腾讯中文词向量（14.3 万词，200 维）。它有明确的覆盖缺口：

```
披萨 False    长颈鹿 False    贝多芬 False    躺平 False    社畜 False
```

猜这些词时直接报「不在词表」——这是**产品级缺陷**，不是精度问题。

而且词向量表天然是「封闭集」：不在表里的词永远算不了。要「开放任意表达」
就不可能靠查表。

## 为什么用 BGE 句向量

BGE（`bge-base-zh-v1.5`）是 BERT 系编码器，把词/短语编码成 768 维向量。
关键性质：**任何汉字串都能编码**，没有 OOV 问题。

```
社畜 → emo(0.42) / yyds(0.40)
躺平 → 摸鱼(0.40) / 内卷(0.40)
```

网络新词也有合理的语义位置。这是「猜词不限」的技术前提。

部署形态：`Xenova/bge-base-zh-v1.5` 的 int8 量化 ONNX，98MB，纯 CPU 推理，
**不需要 torch、不需要 GPU**。单次推理 5.7ms（batch=1）/ 2.9ms（batch=8）。

## 字形干扰：必须处理的坑

BGE 在**短词**上有严重的「同字干扰」——它把共现的汉字当成主要信号。
无处理时：

| 输入 | 原始 Top-6 | 问题 |
|---|---|---|
| 钢琴 | 弹琴 / 钢笔 / 钢铁 / 音乐 / 钢板 / 音乐家 | 钢笔、钢铁、钢板、钢材全错 |
| 冰箱 | 箱子 / 冰盖 / 油箱 / 冰层 / 冰块 / 冰水 | 油箱、风箱错 |
| 大夫 | 一夫 / 御史大夫 / 丈夫 / 工夫 / 姐夫 / 大公 | 一夫、工夫、姐夫全错 |

试过换更大的 `bge-large`——**不解决**。这是 BERL 类模型在 2 字词上把字形
当成了主要语义信号，不是模型容量问题。

### 解法：字符重叠惩罚

```
排序分 = 语义相似度 − penalty × 共享汉字比例
共享汉字比例 = |A ∩ B| / min(|A|, |B|)
```

`钢琴` vs `钢笔` = 0.5（共享「钢」），`钢琴` vs `音乐` = 0（无共享字）。

`penalty = 0.15` 时：

| 输入 | 惩罚后 Top-6 |
|---|---|
| 钢琴 | 音乐 / 音乐家 / 乐器 / 演奏 / 乐曲 / 协奏曲 |
| 冰箱 | 电器 / 箱子 / 空调 / 柜子 / 容器 / 封冻 |
| 大夫 | 医生 / 医务 / 科长 / 医治 / 主任 / 就诊 |

**原始余弦相似度照常输出**，惩罚只作用于名次与排序。
所以界面上的百分比仍是「语义有多近」，不会被惩罚项改写。

### 代价

真正的近义词若有共享字会被轻微扣分（`铁路/地铁` 共享「铁」）。
实测这个误伤远小于不惩罚时的字形干扰——检索基准里前 200 命中率是 90%，
不惩罚时明显更差。

参数在 `data/engine_config.json`：

```json
{ "char_penalty": 0.15, "semantic_blend": 1.0 }
```

## 检索质量基准

`tests/retrieval_bench.py` 用 10 个答案 × 5 个「人类会先想到的词」测名次：

```
钢琴   音乐:1, 乐器:2, 乐曲:8, 小提琴:6, 演奏:4
苹果   水果:2, 香蕉:45, 橘子:25, 果树:6, 果汁:59
地铁   火车:10, 公交:3, 车站:6, 高铁:12, 交通:9
谎言   说谎:2, 欺骗:1, 假话:3, 骗子:4
```

| 指标 | 结果 |
|---|---|
| 前 10 命中 | 45% |
| 前 50 命中 | 69% |
| 前 200 命中 | 90% |

这个基准是判断「引擎能不能撑起游戏」的核心指标：
如果人类认为最相关的词都排不进前 200，游戏就不可玩。

值得注意的是**词表扩到 2.2 万后，前 200 命中率从 78% 升到 90%**——
很多「相关词」之前根本不在词池里，导致名次算不出来。词表覆盖和检索质量是耦合的。

## 换词表为什么是安全的

词表只影响三件事：

1. **谜底从哪抽**（`Engine.words`）
2. **名次的分母**（词池越大，同一个词的 rank 越大）
3. **展示用的规模数字**

它不影响相似度本身——相似度是「答案 ↔ 猜词」两个向量直接算的，
和词池无关。所以：

```bash
python scripts/build_wordlist.py --min-freq 100   # 换口径
python scripts/build_embeddings.py                # 重算向量与邻居
python scripts/audit_pool.py                      # 复核常见词覆盖
```

换完游戏逻辑一行不用改。代价是要重建邻居表（2.2 万词约 5 分钟）。

## 性能

| 环节 | 耗时 | 频率 |
|---|---|---|
| 全池编码 | ~3 分钟（2.2 万词） | 一次性，构建时 |
| 邻居表构建 | ~5 秒 | 一次性，构建时 |
| 启动加载 | ~0.4s | 每次启动 |
| 猜词（池内） | < 2ms | 每次猜词 |
| 猜词（池外） | ~6ms | 每次猜词 |
| 首次猜词建名次表 | ~40ms | 每局一次 |

名次表每局只建一次（`Store._prime`），之后是字典查表 O(1)。
