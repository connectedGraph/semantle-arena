# Agent 设计说明

这份文档解释「为什么 Agent 是这么设计的」，不只是它做了什么。
评审关心的通常不是「你接了个 LLM」，而是**你给它的信息边界是否公平**。

## 一句话

Agent 是一个**信息受限的猜词者**：它看不到答案，只能通过一次批量试探
拿到「每个词和答案的语义距离」，然后自己决定下一步猜什么。

## 工具面：只有两个，且都不泄露答案

```python
guess(words: string[])   # 批量猜词，最多 64 个
                         # → [{word, similarity_pct, rank, level, is_target}]
review(k: int = -1)      # 把自己猜过的词按接近度重排
                         # → 同上结构，但只有已猜过的词
```

设计上的三个克制：

1. **没有 `view_answer_neighbors`**。上一版（`chinese-semantle-agent`）有过
   `view_topk` 直接返回答案的 Top-K 邻居——那等于把答案列表递过去，
   游戏不成立。现在 `review` 只整理 Agent **自己产生过**的数据，
   信息量严格不超过它已知的东西。

2. **`rank` 是相对位置，不是绝对答案**。rank 定义在「词池里离答案多近」，
   是 0~3000+ 的序数，不给候选词本身。Agent 知道「我是第 300 名」，
   但不知道「第 1 名是谁」。

3. **不提供 `hint`**。人类可以放弃，Agent 不能要提示。

## system prompt 里的四条策略

不是装饰，每条都对应一次实测失败：

| 策略 | 触发它的实测现象 |
|---|---|
| 「猜测词要和答案字数一致」 | Agent 一直在猜单字（树/鸟/山），得到 60~68% 的扁平分数，误以为没方向。实际双字词在句向量空间里和单字距离普遍偏远，单字分天然低 |
| 「优先看 rank，不要只看相似度」 | 短词余弦分普遍挤在 60%~70%，区分度接近零；rank 是在 2.2 万词里排出来的相对位置，信号强得多 |
| 「连续 2~3 轮打转就换维度」 | 首版一局 10 步全耗在「树→森林→叶→根→松→柳」这一簇上，因为每步都「稍微高一点」 |
| 「某个词明显突出就沿它发散」 | 与上一条互补：防止过度发散，把有效信号也丢掉 |

## 词数才是代价

**胜负按猜中时用掉的词数算，少者胜。** 不按回合，也不按时间。

第一版按回合算：一次 `guess` 带 64 个词也只算「一个回合」。这在逻辑上说得通
（一次思维决策），但放到人机对比里不公平——人类一次只能交一个词，
Agent 却可以撒网。用户试玩后指出了这一点，改成按词数。

按时间更不对：模型回得快是速度优势，和猜词能力无关。

实现上：

- `Game.until_solved_guesses()` 数到「命中那一刻」为止交了几个不同的词；
- 重复提交的词（`reused`）不计数；
- 猜中之后继续猜的部分不计入——否则先猜中的人反而可能因继续试探而「输」；
- `Race.human_cannot_win()`：Agent 用 N 个词命中后，人类已用 N 个词仍未命中，
  就直接结算（第 N 个词命中是平局，超过就不可能翻盘），不用等玩家点放弃。

口径改了，prompt 必须跟着改。原 prompt 鼓励「开局并行提交一组词」「多传几个」，
在词数口径下等于让 Agent 自己拖垮自己。现在明确告诉它「一次交 20 个词就是 20 个词的代价」，
开局 6~8 个、之后每轮 2~5 个。同一道「钢琴」，改前 32 个词猜中，改后 15 个。

## 并行工具调用

模型可以在**同一轮**发出多个 `tool_call`（比如同时 `guess` 和 `review`），
后端用 `asyncio.gather` 并发执行。`review` 不产生新词、不计成绩，
和 `guess` 并行只是省一次模型调用。

## 界面上的信息边界

人机对战里，Agent 面板**默认隐藏**：猜测表、推理轨迹、词数、是否命中都不显示，
只露「进行中 · 第几步」。结算（`race_end`）时自动揭晓。

只藏猜测表是不够的——早期版本隐藏了表格，但头部仍显示「63 词 · 命中」，
玩家一眼就知道「它已经赢了、用了 63 个」，同样破坏比较。
局中可以手动「揭晓」，按钮上写明代价。

## 为什么用 OpenAI 兼容接口

`LLMClient` 只依赖 `/chat/completions` + `tools` 字段。默认指向本机网关
（`http://127.0.0.1:8787/v1`），改两个环境变量就能切到 DeepSeek 官方或任何
兼容服务。这样「用哪个模型」是可替换的研究变量，而不是绑死在产品里。

## 已知的 Agent 局限

- **相似度对短词不敏感**：BGE 对 2 字词的区分度有限，60%~70% 这一段几乎是噪声。
  `rank` 缓解了这个问题，但没根治。已改用腾讯词向量，见 [docs/engine.md](./engine.md)。
- **没有外部知识**：Agent 不知道「钢琴属于乐器」这种常识，只能从试探里学。
  给工具加一个「类别提示」会显著提升表现，但也会改变「信息受限」这个前提，
  所以默认不做。
- **单轮幻觉**：偶尔模型会声称「命中」但实际没有。判定只认后端返回的
  `is_target`（词 == 答案），不采信模型的自我报告。
